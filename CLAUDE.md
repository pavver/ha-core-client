## Commands

```bash
cargo build
cargo clippy --all-targets                    # should stay warning-free
cargo test                                    # unit tests + tests/client.rs (mock HA server) + doctests
cargo test --test client reconnect            # one integration test by name filter
cargo test --lib triggers                     # unit tests of one module
cargo check --no-default-features --features rustls-tls   # alternate TLS backend
cargo run --example demo                      # read-only tour against a real HA instance
RUST_LOG=ha_core_client=trace cargo run --example demo   # trace shows raw WS traffic (<<< / >>>)
```

The demo reads `HA_URL`, `HA_TOKEN` and optional `DEMO_ENTITY` from `config.json` (git-ignored; template in `config.example.json`).

## Architecture

Library crate (edition 2024) wrapping the Home Assistant WebSocket API as a handle/runner actor. `ARCHITECTURE.md` has the full picture. The parts that span several files:

- **`HAClient` (`src/lib.rs`)** holds `mpsc::Sender<Command>` plus `Arc<Shared>` (`src/runner.rs`: config, shutdown `watch`, `ConnectionState` `watch`). Methods send a `Command` (`src/subscription.rs`) with a `oneshot` responder and await it with the request timeout. Request-style commands return the raw `result` `Value`, and typed parsing happens in `lib.rs`.
- **`Runner` (`src/runner.rs`)** is the only owner of the WebSocket and all state. `run()` alternates a *session* (`select!` over shutdown, frames, commands, housekeeping tick) with an *offline* phase (backoff + reconnect, commands answered with `NotConnected`). It keeps only a `WeakSender`, so dropping every user handle stops it.
- **Message ids restart at 1 per connection.** HA rejects non-increasing ids (`id_reuse`). Subscriptions have a stable client id (`Subscription`) and a per-connection HA id, linked by `routes`. Re-subscription goes in `BTreeMap` order.
- **`Pending` entries** (one per sent request, with deadline) carry a `PendingKind` that decides how the `result`/`event` is handled. `StateOnce` implements `get_state` via a one-shot `subscribe_entities` that is unsubscribed after the first event.
- **`SubKind`** decides how event payloads become `events::Event`. `subscribe_entity` is a server-side `state` *trigger* converted to `Event::StateChanged`. Each subscription has a worker task that runs callbacks sequentially.
- **`src/connection.rs`** only does connect + `auth` handshake. The first connect is done in `HAClient::connect` (errors returned to caller). `auth_invalid` while reconnecting is terminal (`ConnectionState::AuthFailed`).

Conventions:
- String-valued HA enums (`Domain`, `Service`, `FanMode`, `DeviceClass`, `UnitOfMeasurement`, …) are generated by `string_enum!` (`src/state/macros.rs`) with an `Other(String)` fallback. Use it for any new open-ended HA value set. Strum is used only for closed sets (`HvacMode`, `LockState`, …).
- Attribute deserialization must never fail (`events/attributes.rs` falls back to untyped). One bad entity must not break `get_states`.
- `HaState` serializes via `Display` (plain state string). Trigger durations use `HH:MM:SS` (`triggers.rs::ha_duration`).
- Domain helpers live in `src/context_helpers/<domain>.rs` as `impl HAClient` blocks over `call_service`.
- Wire-format unit tests use payload shapes captured from a real HA instance, anonymised. Behavioural changes to the runner need a scenario in `tests/client.rs` (`MockHa` asserts strictly increasing ids).
- Logging goes through `log` only. Never log the access token (`ClientConfig`'s `Debug` redacts it).
